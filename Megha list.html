INTERNAL LOGIC
──────────────
1. Subscribe to `auth().onAuthStateChanged` (native) or `onAuthStateChanged(auth, ...)` (web). When user logs in:
   a. Set user + uid.
   b. Pull custom claims via `await user.getIdTokenResult(true)`. Read `claims.rail`, `claims.banned`.
   c. Subscribe to Firestore `/users/{uid}` onSnapshot. Sync profile fields (handle, home, role, onboarding.completed).
   d. Set status: `banned ? 'banned' : 'authenticated'`.
2. On sign-out: unsubscribe Firestore listener, clear state, set status to 'unauthenticated'.
3. On token refresh event (`auth().onIdTokenChanged`): re-fetch claims, update banned/role.
4. `getIdToken(forceRefresh)`: returns `await user.getIdToken(forceRefresh ?? false)` or null if not signed in. Used by API call helpers.
5. `refreshProfile()`: one-shot Firestore re-read of `/users/{uid}`, in case the realtime listener missed an update (rare but possible).
